一个基于本地知识库的agent问答助手 

背景：门店设备手册以 PDF 为主，查一个参数要翻几十页，售后问题重复回答。独立完成从文档解析、切分、向量化到检索生成的完整 RAG 链路，支持图文对照与答案溯源。

双工作流编排：用 LangGraph 拆成导入链（PDF→Markdown→图片摘要→层级切分→商品名识别→向量化→入库，8 节点）与查询链（三路并行检索 → RRF 融合 → cross-encoder 精排 → 自适应 top_k → 生成），两条链职责隔离、节点可单独重跑。

切分策略针对手册结构定制：按 Markdown 标题层级切块并保留父级标题路径作为元数据，表格做线性化处理；相比定长切分，技术参数类问题的召回显著提升。

三路召回 + 两段排序：dense/sparse 混合检索、HyDE 假设文档检索、Web 搜索并行执行，用 RRF 解决多路分数不可比的问题保召回，再用 BGE-Reranker 精排保精度，最后按 rerank 分数的“断崖”动态决定 top_k，避免固定 k 造成的噪声或截断。

实体对齐 + 澄清机制：先从 query 抽取商品型号与库内商品名做向量对齐，命中则作为强制过滤条件，未命中返回候选让用户确认——用一次澄清换掉幻觉，比让模型硬答更可控。

搭建离线评测体系（核心亮点）​：人工标注 20 条 query（标准 chunk + 答案要点），脚本化计算 Recall@5 / nDCG@10 / MRR / 上下文要点覆盖 / 陈述级 faithfulness；LLM 判官按「prompt 版本 + 模型 + 输入哈希」三级缓存，历史读写打桩、默认禁网保证可复现，全缓存复跑 1.4s 结果完全一致。

指标与定位：Recall@5 0.975、nDCG@10 0.991、MRR 1.000、faithfulness 0.932；据此定位出“上下文给全了但答案漏要点”（context recall 1.0 vs 答案要点覆盖 0.817）的生成侧瓶颈，以及“多要点问题被动态 top_k 截断”（双标准答案用例 R@5 仅 0.5）的策略缺陷。

工程化：导入/问答双服务拆分 + 一键启动器（端口预检、就绪探测、日志分流、任一进程崩溃联动退出）；SSE 分 progress/delta/final 三类事件驱动前端进度与流式输出；节点级耗时埋点；客户端单例用双重检查锁。
